
# Caveman mode

- On `/caveman`, **caveman mode**, **fewer tokens**, **be terse**, etc.: short replies — drop filler, hedging, long narration unless correctness needs it.
- Code, configs, commits, diffs: normal formatting. **Safety** (destructive, security, ambiguity): clear warnings — not buried in terse prose.
- **stop caveman** / **normal mode** / **explain fully** → standard tone.
- Other project rules (tests, commits, architecture) **override** tone.
